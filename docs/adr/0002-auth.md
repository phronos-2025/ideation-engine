# ADR 0002 — Authentication (single-user, edge-gated)

**Status:** accepted (Phase 0) · **Date:** 2026-06-22

## Decision

- **Cloudflare Access** in front of `phronos.org`, with a policy that allowlists
  exactly one federated identity (Google or GitHub). Unauthenticated traffic
  never reaches Vercel or Railway.
- The browser calls the **Vercel** front end; Vercel's server proxies to the
  **Railway** API, presenting a shared **`API_SERVICE_TOKEN`** (the Vercel↔Railway
  trust boundary) and forwarding the verified identity as `x-actor-email`.
- The API derives a stable `event.actor_id` from that identity
  (`actorIdFromIdentity`, a deterministic v5-style uuid). No user table, no
  password store (invariant #11).

## Rationale

Right-sized for one user: "let me in, keep everyone else out." The federated
account (with MFA/passkey) is the real perimeter. There is nothing to brute-force
because there is no login form in the app.

## Consequences

- Agents never use this path (invariant #12); they run server-side with a service
  credential and are isolated on their own Neon branch (Phase 3).
- **Deploy hardening (open):** the API currently trusts the service token + the
  forwarded `x-actor-email`. At deploy we additionally verify the raw
  `Cf-Access-Jwt-Assertion` against the team JWKS for defense in depth (see
  `runbooks/cloudflare.md`, written at deploy time).
- Local dev has no Cloudflare; the API falls back to `ALLOWED_IDENTITY` and still
  requires the service token (fail-closed).
